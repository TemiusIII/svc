# Нагрузочный тест (ДЗ 2)

Тест на k6: смешанный профиль по весам и одиночная тяжёлая операция.
Открытая модель нагрузки (`constant-arrival-rate`): частота в запросах
в секунду, длительность ступени — параметрами запуска.

## Профиль нагрузки

| Операция | Вес | Обоснование |
|----------|-----|-------------|
| Свободные слоты (GET /slots) | 22 | пациент смотрит сетку перед записью, чаще всего |
| Специалисты (GET /specialists) | 18 | выбор специалиста — первый шаг сценария |
| Мои записи (GET /appointments) | 15 | проверка своих записей после каждой брони |
| Главная (GET /) | 12 | вход в сервис |
| Карточка специалиста (GET /specialists/{id}) | 12 | тот же выбор: кто принимает |
| Бронирование (POST /book) | 9 | итог сценария: пациентов меньше, чем просмотров |
| Специалисты с фифильтром | 8 | узкий поиск по специальности |
| Сводка (GET /summary) | 2 | смотрит администратор клиники, не пациент |
| Отмена (POST /cancel) | 2 | треть бронирований в тесте отменяется |

## Запуск

Перед каждым испытанием база наполняется заново (операции записи
добавляют данные):

```bash
python db/seed.py full
k6 run load/tests/step.test.js -e SCENARIO=mixed -e RATE=4 -e DURATION=30s
k6 run load/tests/step.test.js -e SCENARIO=heavy  -e RATE=2 -e DURATION=30s
```

Порог (методичка, п. 2.1) записан в thresholds теста: p95 < 500 мс,
доля ошибок < 1 %. Отказы по правилам варианта (409 slot_busy /
slot_overlap, 404 not_found) — ожидаемые ответы, ошибками не считаются
(validator `checkBook`/`checkCancel`).

## Параметры

`RATE` — частота, запросов/с; `DURATION` — длительность ступени;
`LIMIT_MS` — порог p95 (по умолчанию 500); `ERROR_RATE` — порог ошибок.

Вход выполняется один раз в `setup()` и в результаты не попадает.

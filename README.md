# Сервис записи на приём

Хранит расписание специалистов клиники слотами: по выбранной услуге показывает
свободные слоты подходящей длительности и бронирует один из них, не допуская
наложения на существующие записи. Отмена записи возвращает слот в свободные.
Сводка показывает загрузку специалистов за период и долю отменённых записей.

Учебный сервис курсовой работы по дисциплине «Оптимизация клиент-серверных
приложений», НИТУ «МИСИС», вариант 3. Префикс работ — `artem_smirnov`.

## Требования

- Python 3.12 (проверено на 3.12.16);
- PostgreSQL 16 (проверено на 16.2);
- зависимости из `api/requirements.txt`;
- k6 0.50+ — только для нагрузочного теста из ДЗ 2 (каталог `load/`).

## Установка и запуск

```bash
git clone <адрес репозитория>
cd booking-service
pip install -r api/requirements.txt
cp .env.example .env                # заполнить переменные
createdb artem_smirnov              # или любым способом создать базу
psql -d artem_smirnov -c 'CREATE SCHEMA artem_smirnov; CREATE USER app PASSWORD "changeme";'
python db/seed.py small             # применить схему и малое наполнение
python api/run.py                   # сервис поднимется на APP_PORT
```

Рабочее наполнение (200 000 слотов, 60 000 записей):

```bash
python db/seed.py full
python db/seed.py counts            # сколько записей в таблицах сейчас
```

Наполнение детерминированное (`random.seed(42)`): повторный запуск даёт тот же
результат. Перед каждым нагрузочным испытанием база наполняется заново.

## Переменные окружения

| Переменная | Назначение | Пример |
|------------|------------|--------|
| DATABASE_URL | подключение к базе (SQLAlchemy/asyncpg) | postgresql+asyncpg://app:changeme@localhost/artem_smirnov |
| DB_SCHEMA | схема базы данных | artem_smirnov |
| SEED_DSN | DSN для генератора наполнения (asyncpg) | postgresql://app:changeme@localhost/artem_smirnov |
| APP_PORT | порт сервиса | 8080 |
| APP_POOL_SIZE | размер пула соединений к базе | 10 |

Подключение через unix-сокет: в DATABASE_URL и SEED_DSN после `@` идёт
`/база?host=/путь/к/сокету`. Параметры `connect_args` движка уже настроены.

## Проверка работоспособности

Интерфейс открывается по адресу `http://localhost:8080`, учётная запись для
проверки — `demo` / `demo`. На главной странице виден список услуг; кнопка
«Свободные слоты» открывает сетку слотов, «Записаться» бронирует слот.
Тесты запускаются командой:

```bash
python -m pytest
```

## Программный интерфейс

| Метод и путь | Параметры | Ответ | Ошибки |
|--------------|-----------|-------|--------|
| GET /login | — | страница входа 200 | — |
| POST /login | login, password | 302 на `/` + кука `booking_user` | 302 на `/login?error=1` при неверной паре |
| POST /logout | — | 302 на `/login`, кука удалена | — |
| GET / | — | 200 страница услуг | 302 без куки |
| GET /specialists | page, speciality | 200: список специалистов, постранично, `Показано N из TOTAL` | 302 без куки |
| GET /specialists/{id} | — | 200 карточка: услуги и последние 10 записей | 302 если не найден или нет куки |
| GET /slots | service (обязателен), from | 200: свободные слоты услуги на 7 дней от даты | 302 без service/без куки |
| POST /book | slot_id, client_name | 201 `{"ok": true, "appointment_id": N}` | 404 `slot_not_found`; 409 `slot_busy`; 409 `slot_overlap`; 302 без куки |
| POST /cancel | appointment_id | 200 `{"ok": true}` | 404 `not_found` (чужая/несуществующая); 409 `already_cancelled`; 302 без куки |
| GET /appointments | page | 200: мои записи, постранично | 302 без куки |
| GET /summary | days (1–365) | 200 сводка: загрузка специалистов, доля отмен | 302 без куки |

У всех операций есть заголовок `X-Response-Time-ms` — им снимаются все замеры.
Отказы по правилам варианта (`slot_busy`, `slot_overlap`, `already_cancelled`)
— ожидаемые ответы, в нагрузочном тесте они не считаются ошибками.
